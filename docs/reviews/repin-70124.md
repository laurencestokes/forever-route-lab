# Re-pin to client build 1.60.1.70124: diff report

Done 2026-09-30, under D-050 item 1. The owner's Forever beta client updated itself from
1.60.1.70009 to 1.60.1.70124. Every tool that reads the client was re-pinned to the new build. Every
client-derived dataset was then rebuilt twice and compared byte for byte.

**Result.** Nothing that this project reads from the client changed between the two builds:
- Every DB2 table, terrain file, minimap texture and painted-map tile that the tools read keeps its
  content key (CKey).
- Every rebuilt data file is byte-identical to the one built at 70009.
- Only the provenance records change: the manifests, the NOTICEs, the minimap pack pointer, the
  build string inside the three client tables, and one hash in the tint file.

No committed decision or design assumption is affected. Review finding MD-01 and gate G13 are
cleared.

## 2. Method

1. **Layouts.** All 19 DB2 tables in the generated layouts were read at 70124 with the 70009 WoWDBDefs
   blocks. Every file carries the layout hash that `parseWdc5` checks on each read, so the layouts are
   kept (`LAYOUT_BUILD` stays `1.60.1.70009`).
2. **CKeys, before any rebuild.** The CKeys the 70009 manifests and reports recorded were compared
   with the 70124 root. All of them are equal:

   | What | Compared |
   |---|---|
   | DB2 tables with a recorded 70009 CKey | 16 of 16. GameObjects and TransportAnimation were never recorded, so they were not compared. |
   | Navigation inputs over the 136 stage-1 blocks | 13,332 distinct files |
   | Terrain byproduct inputs (WDT and root ADTs) | 740 on the Eastern Kingdoms, 992 on Kalimdor |
   | Minimap textures | 1,796, plus 3 WDTs |

3. **Rebuilds.** Each dataset was rebuilt on the new pin, then rebuilt again with `--check`, which
   compares every byte. The 70009 outputs were copied first to `.cache/repin/before/`, with the
   minimap tiles, and each rebuild was compared with that copy file by file. The scripts and logs are in
   `.cache/repin/`.

## 5. The DB2 rows and the placeholder

At 70124, `UiMap` and `UiMapAssignment` have the CKeys they had at 70009. The local geometry that
`import.ts --build 1.60.1.70124` writes passes L4 against the committed placeholder: all 61 rows are
identical, the 12 `db2-csv` rows included. So the committed placeholder is unchanged, and
`import.ts --placeholder --check` passes.

The rows file `tools/maps/inputs/db2-rows-1.60.1.70009.json` keeps its name and its 70009 citations,
because the CSVs it cites (file, line and SHA-256) are of that build. `DB2_BUILD` stays `1.60.1.70009`.
The app's geometry line therefore still reads "12 rows @ 1.60.1.70009", which is accurate.

Relabelling the rows to 70124 would need either 70124 CSVs (a download) or a rows format that cites a
client extraction. It would also change the placeholder's content hash. **This is the architect's
call**; the recommendation is to keep the rows as they are.
